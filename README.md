# FartSpace — Android app (Capacitor)

Free native Android wrapper around the FartSpace website at
https://fartspace.netlify.app/ — same files, same live Supabase feed.

- **App name:** FartSpace
- **appId:** `com.shatteredlayerstudio.fartspace` (permanent — never change it)
- **Version:** 1.0 (versionCode 1)
- **iOS:** skipped on purpose — K only uses Android.
- **Cost to build:** $0. Google Play listing is a separate $25 one-time
  fee, paid by K — see `PLAY_STORE.md`.

## Layout

| Path | What it is |
|---|---|
| `capacitor.config.json` | App id / name / web folder (`www`) |
| `www/` | The web app, copied from `~/workspace/fartspace-public/` (index, app.js, config.js, admin.html, manifest, sw.js, icons) |
| `android/` | The native Android project (Gradle). Generated by `npx cap add android` |
| `PLAY_STORE.md` | Plain-English guide: build, sign, $25 fee, 12-tester closed test, store listing |
| `.github/workflows/build-android.yml` | **GitHub Actions build (recommended)** — builds the debug APK + unsigned release AAB in the cloud, free |
| `.gitignore` | Keeps node_modules, build output and keystores out of GitHub |
| `sync-web.sh` | Copies the latest website files into `www/` + runs `npx cap sync android` — **local Muse VM only** (it copies from `~/workspace/fartspace-public`, which does not exist on GitHub) |

## Build — GitHub Actions (recommended, free)

The Muse VM cannot build this locally (see "Status" below), so the
build runs in GitHub's cloud instead — free on the GitHub free plan.

1. K creates a free GitHub account and a repo, and pushes this whole
   folder to it (see `PLAY_STORE.md`, Option B — step by step).
2. The workflow runs automatically on every push to `main`, or by
   pressing **Run workflow** in the repo's Actions tab.
3. When it finishes, download the two files from the run's Artifacts:
   - **`fartspace-debug.apk`** — test version, install it on your
     phone to try the app.
   - **`fartspace-release-unsigned.aab`** — the release file Google
     Play wants, but **unsigned** — Play will not accept it until it
     is signed with your release keystore (see `PLAY_STORE.md`).

## Build — local (only works off this VM)

```bash
export JAVA_HOME=~/jdk17
export ANDROID_HOME=~/android-sdk
export PATH=$JAVA_HOME/bin:$PATH
./sync-web.sh
cd android
./gradlew assembleDebug    # test APK: android/app/build/outputs/apk/debug/app-debug.apk
./gradlew bundleRelease    # release .aab for Google Play (needs signing key)
```

Needs JDK 17 and Android SDK API 36 + build-tools 36 (Capacitor 8).
Full steps, including the Play Console $25 fee and the 12-tester /
14-day closed test, are in `PLAY_STORE.md`.

> **Status 2026-11-22: no debug APK exists yet.** The project is ready
> and the toolchain is installed on this VM (JDK 17 at `~/jdk17`,
> Android SDK at `~/android-sdk`, Gradle 8.14.3 at `~/gradle-8.14.3`),
> but the build cannot download Gradle dependencies here: this VM's
> network policy blocks direct TCP from Java processes ("Other TCP
> connections is turned off"). Fix: in the Muse app, Settings →
> Permissions → Direct network protocols, switch **other_tcp from Deny
> to Ask**, then run the build above. **That setting is not visible in
> the Android Muse app** (K checked — the Permissions screen there
> ends at "Spaces and scheduled tasks"); it is on the web version of
> Muse instead. The easy way round it is the GitHub Actions build
> above — no setting change needed, and no changes to the project
> are needed either way.

## Notes

- `config.js` contains the Supabase Project URL + **anon publishable**
  key only. That key is meant to be public — it is the same key shipped
  in the website. Never put a `service_role` (secret) key in here.
- The service worker (`sw.js`) caches the app shell only. Supabase API
  calls always go to the network, so the feed stays live.
- After any website change, run `./sync-web.sh` and rebuild, and bump
  `versionCode` / `versionName` in `android/app/build.gradle` for a
  Play release.
